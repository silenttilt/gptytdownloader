# YouTube Downloader для Tampermonkey

Userscript добавляет кнопку **«Скачать»** на страницы видео и Shorts. Обложки скачиваются непосредственно в браузере. Видео скачивает **локальный** Python-сервер на `127.0.0.1:8765` через yt-dlp; при необходимости FFmpeg объединяет видео и звук. Сервер должен работать на том же компьютере, где открыт браузер. Запуск в облачной среде сам по себе не подключает к нему домашний браузер.

Проект не использует сайты-конвертеры, платные API, cookies или авторизацию YouTube и не обходит DRM, платный доступ, возрастные, географические и другие ограничения. Скачивайте материалы, для которых у вас есть разрешение.

## Структура

```text
youtube-downloader/
  userscript/
    youtube-downloader.user.js
  backend/
    server.py
    requirements.txt
  tests/
    requirements.txt
    test_backend.py
    test_userscript.py
    test_media_integration.py
    test_userscript_helpers.cjs
  README.md
```

## Установка

### 1. Tampermonkey и userscript

1. Установите [Tampermonkey](https://www.tampermonkey.net/) из официального магазина расширений для Chrome, Edge или Firefox.
2. Откройте панель Tampermonkey → **Создать новый скрипт**.
3. Замените содержимое редактора полным содержимым `userscript/youtube-downloader.user.js`, сохраните скрипт и включите его.
4. Разрешите userscripts в настройках расширений браузера, если актуальная версия Chrome/Edge требует этого. При первом запросе разрешите Tampermonkey соединения с `127.0.0.1` и `i.ytimg.com`.
5. Откройте YouTube или обновите уже открытую вкладку. Скрипт обрабатывает дальнейшие переходы YouTube без перезагрузки.

Для вкладки **«Обложка»** больше ничего устанавливать не нужно. При отключённом разрешении Tampermonkey на загрузки скрипт использует скачивание уже проверенного изображения через Blob; браузер может запросить разрешение на сохранение файла.

### 2. Python и зависимости

Требуется Python **3.10 или новее**. Установите его с [python.org](https://www.python.org/downloads/) или через пакетный менеджер ОС. На Windows включите добавление Python в PATH.

Все дальнейшие команды выполняются из каталога `youtube-downloader`.

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

В зависимостях закреплена версия yt-dlp с официальным пакетом решателя JavaScript-задач `yt-dlp-ejs`. Это библиотека Python, отдельный бинарный yt-dlp не нужен. Установите также актуальный **Node.js LTS (22+)** с [nodejs.org](https://nodejs.org/), чтобы yt-dlp мог обрабатывать JavaScript-задачи YouTube. Сервер использует найденный в PATH Node; без него YouTube может не отдать форматы. Не отключайте проверку TLS.

### 3. FFmpeg

FFmpeg необходим для раздельных видео- и аудиопотоков, в том числе большинства вариантов высокого качества. Нужны обе команды — `ffmpeg` и `ffprobe` — в PATH.

```bash
# Ubuntu / Debian
sudo apt-get update
sudo apt-get install ffmpeg

# macOS с Homebrew
brew install ffmpeg
```

Windows PowerShell:

```powershell
winget install --id Gyan.FFmpeg --exact
```

После установки откройте новый терминал и проверьте:

```bash
ffmpeg -version
ffprobe -version
node --version
```

Без FFmpeg сервер предлагает только доступные готовые форматы, уже содержащие звук. Если таких форматов нет, он объясняет, что нужно установить FFmpeg. Видео не перекодируется: MP4 выбирается при совместимых потоках, иначе возвращается WebM или MKV с указанием реального контейнера.

### 4. Токен и запуск сервера

Сервер создаёт криптографически случайный токен в локальном пользовательском файле при первом запуске. Узнать токен для настройки userscript:

Файл по умолчанию: `~/.config/youtube-downloader/token` на Linux/macOS или `%LOCALAPPDATA%\youtube-downloader\token` на Windows.

```bash
.venv/bin/python backend/server.py --show-token
```

Windows:

```powershell
.venv\Scripts\python.exe backend\server.py --show-token
```

Токен выводится только этой отдельной командой; не публикуйте его и не добавляйте его файл в Git. Это ключ вашего локального API, а не пароль или cookie YouTube.

Запуск Linux / macOS:

```bash
.venv/bin/python backend/server.py
```

Запуск Windows:

```powershell
.venv\Scripts\python.exe backend\server.py
```

Оставьте терминал открытым. Остановка — `Ctrl+C`. Сервер слушает только `127.0.0.1:8765`; не открывайте порт наружу и не создавайте публичный туннель.

По умолчанию видео сохраняются в `~/Downloads/YouTube`. Другой каталог и другой файл токена можно указать явно:

```bash
.venv/bin/python backend/server.py --download-dir "$HOME/Videos/YouTube" --token-file "$HOME/.config/youtube-downloader/token"
```

При использовании `--token-file` передавайте тот же путь команде `--show-token`. Параметры командной строки не передаются пользователями через HTTP API.

### 5. Подключение userscript

Откройте видео → **«Скачать»** → вкладка **«Видео»**, вставьте токен в поле настроек локального сервера и сохраните. Токен хранится через `GM_setValue`, а не в `localStorage` страницы YouTube. Адрес сервера фиксирован: `http://127.0.0.1:8765`.

Проверка сервера и каждый запрос API требуют токен. Браузерные запросы с Origin разрешены только для `https://www.youtube.com`, `https://youtube.com` и `https://m.youtube.com`. Tampermonkey может не передавать Origin для привилегированного GM-запроса: такие запросы разрешены **только с правильным токеном**. Чужой Origin и `Origin: null` отклоняются. CORS не заменяет проверку токена.

## Использование

- **Обложка:** откройте вкладку «Обложка», дождитесь предпросмотра и выберите максимальное либо конкретное доступное разрешение. Нажмите «Скачать обложку». Имя файла: `название_видео_thumbnail.jpg`. Адреса — исключительно официальные `i.ytimg.com`. Если `maxresdefault.jpg` отсутствует или содержит заглушку, автоматически выбирается следующее доступное изображение.
- **Видео:** запустите Python-сервер, настройте токен, выберите «Лучшее доступное» или одно из найденных качеств `360p`, `480p`, `720p`, `1080p`, `1440p`, `2160p`. Недоступные варианты не показываются. Рядом с качеством указан контейнер.
- Меню показывает подготовку, скачивание, обработку, завершение или ошибку. Прогресс отображается, когда yt-dlp сообщает объём. Повторные клики не создают параллельные копии той же активной задачи. Завершённое видео находится в каталоге **сервера**: повторная загрузка файла через браузер не требуется.
- Для Shorts используется тот же процесс. Кнопка размещается рядом со штатными действиями; если YouTube изменил DOM, предусмотрено резервное размещение. Плеер и штатные кнопки скрипт не изменяет.
- Для вертикальных Shorts качество определяется по короткой стороне: `1080×1920` показывается как `1080p`. Прямые трансляции и будущие премьеры не скачиваются; дождитесь завершения. Без FFmpeg доступны только готовые прогрессивные форматы: HLS может требовать перепаковки даже при наличии звука.

## API

Все основные запросы используют заголовок `X-YTD-Token`. Тело POST должно быть JSON (`Content-Type: application/json`).

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние сервера, доступность FFmpeg, каталог сохранения |
| GET | `/api/formats?url=...` | Название, миниатюра и действительно доступные качества |
| POST | `/api/download` | Принимает `{"url":"https://www.youtube.com/watch?v=dQw4w9WgXc","quality":"best"}`; возвращает `task_id` |
| GET | `/api/tasks/{task_id}` | `preparing`, `downloading`, `processing`, `completed` или `error`; прогресс, результат или ошибка |

Качество — только `best`, `360`, `480`, `720`, `1080`, `1440`, `2160`. Клиент не выбирает команды, пути, yt-dlp-опции или произвольные URL ресурсов. Проверяются YouTube URL, идентификатор видео, размеры запросов, токен и Origin. Работа выполняется в фоновых потоках с ограничением числа задач. История задач хранится в памяти и теряется при перезапуске; файлы сохраняются на диске.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Сервер не отвечает | Запущен ли `server.py` на том же компьютере; разрешил ли Tampermonkey соединение с `127.0.0.1`; не занят ли порт 8765 |
| Неверный токен / HTTP 401 | Скопируйте токен командой `--show-token` с тем же `--token-file`, сохраните его в меню; не копируйте пробелы |
| HTTP 403 Origin | Используйте обычный YouTube в поддерживаемом браузере; запросы с чужих страниц запрещены. Не отключайте проверку Origin |
| Нет высокого качества / нужен FFmpeg | Установите `ffmpeg` и `ffprobe`, проверьте PATH и перезапустите сервер |
| Ошибка JavaScript challenge / нет форматов | Проверьте Node.js 22+, зависимости из requirements и текущую поддержку YouTube в yt-dlp; сайт меняется независимо от проекта |
| YouTube требует вход, подтверждение возраста, сообщает недоступность или блокировку IP | Это ограничение источника, а не проблема токена локального API. Использование чужих cookies и обход ограничений проектом не предусмотрены |
| Обложка 1280×720 не предлагается | У этого видео нет полноценного `maxresdefault`; используется следующее проверенное разрешение |
| Обложка не сохранилась автоматически | Проверьте разрешение Tampermonkey на загрузки и браузерные разрешения; попробуйте резервное скачивание |
| Нет кнопки после изменения сайта | Обновите вкладку, проверьте включение userscript. Shadow DOM защищает стили, но изменения структуры YouTube могут потребовать обновления селекторов |
| Видео сохранено не на том компьютере | Файл записывается там, где работает Python; backend нужно запускать на компьютере с браузером |

## Проверки

Backend-тесты выполняются без обращения к YouTube: они используют реальный HTTP API на loopback и подменяют только внешнюю библиотеку загрузки. Проверяются аутентификация, Origin, URL, выбор контейнера и качества, фоновые задачи, прогресс и ошибки.

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_backend.py' -v
.venv/bin/python -m unittest discover -s tests -p 'test_media_integration.py' -v
.venv/bin/python -m py_compile backend/server.py
node --check userscript/youtube-downloader.user.js
node --test tests/test_userscript_helpers.cjs
```

Тест `test_media_integration.py` генерирует короткие видео и звук, скачивает их через настоящий yt-dlp по локальному HTTP и объединяет настоящим FFmpeg. Итоговые H.264/AAC-потоки проверяет ffprobe. Только получение метаданных YouTube заменено фикстурой; внешний сайт не вызывается. Если FFmpeg/ffprobe отсутствуют, этот тест явно пропускается.

Для браузерных интеграционных тестов установите **необязательные зависимости для разработки** и Chromium:

```bash
.venv/bin/python -m pip install -r tests/requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m unittest discover -s tests -p 'test_userscript.py' -v
```

На Linux зависимости браузера можно установить командой `.venv/bin/python -m playwright install --with-deps chromium` при наличии соответствующих прав. Тесты также используют системный Chromium, если он доступен. На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`.

Браузерные тесты проверяют настоящий userscript в Chromium с имитацией YouTube, GM API и сетевых ответов: обложки, меню, состояния задач и SPA. Это не проверка установленного расширения Tampermonkey, актуальной страницы YouTube или реальной загрузки видео. Для проверки на вашем компьютере установите userscript в Tampermonkey и выполните скачивание разрешённого публичного видео и его обложки. Часть функций зависит от доступности источника и поведения браузера; об успешной реальной загрузке нельзя судить только по локальным тестам.
